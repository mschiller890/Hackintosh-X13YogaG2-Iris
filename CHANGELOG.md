# Changelog

This changelog covers **this fork** (Lenovo ThinkPad X13 Yoga Gen 2). Status values:
**confirmed** (works on hardware), **testing** (built and installed, being evaluated), **reverted**, **superseded**
(replaced by a later entry).

The full history of the GPU stack this fork is built on lives in the upstream project's git history and in this
repository's [docs/HISTORY.md](docs/HISTORY.md) (how it was done, phase by phase) and [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md)
(what failed and why). The patch-level reference is [docs/CATALOG.md](docs/CATALOG.md); what works and known problems
are in [docs/STATUS.md](docs/STATUS.md).

| 2026-11-03 | **Guard for the `probePortState()+0x207` pure-virtual panic** (NootedGreen **XE-PORTGUARD**, [#8](https://github.com/JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe/issues/8), [#22](https://github.com/JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe/issues/22), [#28](https://github.com/JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe/issues/28)): on three other machines the screen went black when WindowServer opened the framebuffer: after "HPD is high" `AppleIntelPort::probePortState()` calls the port's `probePortMode()` through vtable slot 0x190, which is `___cxa_pure_virtual` on a plain `AppleIntelPort`. `probePortState` is now routed: when that slot is the pure-virtual stub, it calls `setPortMode(0)`, sets the port state (`this+0x554`) to 2 and returns 2, Apple's own result when a sink can't be probed (the fix bencortina570 tested in #28); otherwise it runs Apple's code unchanged. | 2026-10-29 | **Rectangles with a different blur level around hovered elements fixed** (libxedrv v23): in windows with a backdrop blur (the WindowServer window blur used by Tauri/Electron apps, WebKit `backdrop-filter`, `NSVisualEffectView`), moving the pointer over elements made rectangles flash around them. Cause, found by dumping the WindowServer render passes: for partial updates Core Animation builds a copy of the background behind the window (a non-IOSurface texture loaded with `loadAction = Load`) and paints some strips with the `PBGRAXb_Xhf` pipeline; on this driver they come out as (0,0,0,0), and the 27-tap blur spreads them into visible rectangles. libxedrv now skips those draws in WindowServer only, so the strip keeps its previous (correct) background. Recorded 10 s of hover: 35 and 24 frames with artifacts before, 0 and 2 after. Off: `XE_XHF_NATIVO=1`. | 2026-10-28 | **Compute work ordered against render/blit, and working compute barriers** (libxedrv v21): on driver 16.0.32 a compute encoder could run concurrently with the render/blit work before it in the same command buffer, and the serial compute encoder ignores `memoryBarrierWithScope:`, so a dispatch could read data the previous one hadn't written yet (Core Image / MPS blurs that differ from the CPU result). libxedrv now puts an `MTLSharedEvent` signal/wait between compute and render/blit in a command buffer, and turns serial compute encoders into concurrent ones with a driver barrier before every dispatch after the first (`dispatchType` still answers serial). ## Before this fork

This fork's first commit is based on the upstream snapshot at `6f03560` (xe-toque tile mode). The entire GPU acceleration
stack — NootedGreen kernel patches, the MTL17 Metal driver, `libxedrv`, the shader compiler, the VA plugin, the
user-space tools — was developed there. Every entry dated 2026-10-20 through 2026-10-27 in the upstream project's
changelog applies to this fork unchanged (they are GPU-stack fixes, not laptop-specific), and the provenance of each is
preserved in [docs/HISTORY.md](docs/HISTORY.md) and [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md). The upstream repository
is [JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe](https://github.com/JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe);
its git history is the authoritative source for those entries. Issues and PRs cited in the docs (e.g. #21, #3, #16)
point there.
